# 나라장터 입찰공고 법령 위반 모니터링 AI

2026년 [DACON 나라장터 자체입찰 공고 법령 위반사항 모니터링 AI 경진대회](https://dacon.io/competitions/official/236754/overview/description)에 참가하며 만든 실험 기록과 추론 코드입니다. 공고문, 첨부 문서, 나라장터 등록 정보를 읽고 **24개 검토 항목의 위반 여부(0/1)와 근거 문구**를 내는 과제였습니다. 모든 팀은 같은 Gemma 4 26B A4B IT 모델을 사용했고, 모델을 추가 학습시킬 수 없었습니다. 리더보드 점수는 24개 항목의 **양성 F1 평균**으로 계산됐으며, 근거 문구는 별도 정성평가 대상이었습니다. [평가 방식](https://dacon.io/competitions/official/236754/overview/evaluation)

## 어떻게 접근했나

처음에는 공고와 첨부를 문서별로 나누어 Gemma에 보내고 결과를 합쳤습니다. 이후 판단 카드, 제품 코드 정보, 원문 사실 발췌, 항목 그룹화 등을 실험했습니다. 이 과정에서 **문서 조각 수 × 항목 그룹 수**만큼 호출이 늘어 여러 제출이 2시간 제한에 걸렸습니다.

후반에는 공유받은 참고 구현의 아이디어를 분석해 별도의 `src/pps_ai` 코드로 재구성했습니다. 문서에서 금액·날짜·제품 코드·자격요건 같은 사실 후보를 구조화하고, 항목마다 최종 판정 책임을 명시했습니다. Gemma가 필요한 부분을 판단하고, Python은 일부 명확한 관계를 계산하거나 근거 문구가 실제 원문에 있는지 확인했습니다. 이 방식의 첫 완주 제출(S001)이 가장 높은 공개 점수를 냈습니다. 구현 계보와 한계는 [clean 기준선 기록](docs/clean_reference_l41_dev200_result.md)과 [일반화 진단](docs/s001_public_generalization_diagnosis_20260923.md)에 남겼습니다.

## 남은 교훈

긴 원문을 모두 읽히는 것만으로 판정이 좋아지지는 않았습니다. **어떤 문장이 어떤 조건을 충족하는지**를 문서 출처와 함께 정리하고, 항목별 판정·병합 책임을 분명히 하는 편이 효과적이었습니다. 동시에 복잡한 규칙이 dev200의 몇 건만 맞히도록 변하지 않았는지, 호출 수가 실제 2시간 안에 끝나는지를 따로 검증해야 했습니다.

[같은 대회 수상자 인터뷰](https://dacon.io/competitions/official/236754/talkboard/418493)에서 검증 방식을 바꾸고 한 문제에 집중해 수정했다는 회고를 읽었습니다. 제 실험에서도 뒤늦게 한 변경씩 비교하기 시작했지만, 공개 점수로 일반화 성능을 확인할 기회가 부족했습니다. 다음에는 작은 개발셋의 점수 상승을 곧바로 성능 향상으로 해석하지 않고, 입력·출처·실행시간 검증과 독립적인 평가를 먼저 준비하려 합니다.

코드는 [`src/pps_ai`](src/pps_ai), 재현 설정은 [`experiments/manifests`](experiments/manifests), 상세 실험과 실패 기록은 [`docs`](docs)에 있습니다. 초기 구현은 [`legacy`](legacy/pipeline_v1_20260921), 별도 탐색은 [`incubator`](incubator)에 보존했습니다. 대회 원본 데이터와 제출 ZIP은 이 저장소에 포함하지 않았습니다.

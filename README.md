# 나라장터 자체입찰 공고 법령 위반사항 모니터링 AI 경진대회

2026년 [DACON 나라장터 자체입찰 공고 법령 위반사항 모니터링 AI 경진대회](https://dacon.io/competitions/official/236754/overview/description) 참가 기록. 입찰공고의 법령 위반 가능성을 찾아내는 추론 파이프라인을 설계하고, 제출 결과와 실패 원인을 정리했다.

## Overview

- **입력:** 공고문·첨부 문서·나라장터 등록 정보.
- **출력:** 24개 검토 항목의 위반 여부(0/1)와 원문 근거 문구.
- **제약:** 모든 참가자가 고정된 Gemma 4 26B A4B IT 사용. 추가 학습 불가, 제출 코드 추론시간 2시간 제한.
- **평가:** 24개 항목의 양성 F1 평균. 근거 문구는 리더보드와 별도로 정성평가. [대회 평가 기준](https://dacon.io/competitions/official/236754/overview/evaluation)

## Approach

- **초기:** 24개 항목을 Gemma가 직접 판정. 문서 분할·병합, 판단 카드, 제품 정보, 사실 발췌, 항목 그룹화를 차례로 실험.
- **전환:** 공유받은 참고 구현의 구조를 분석해 `src/pps_ai`로 재구성. Python이 원문·메타데이터·공식 자료에서 금액, 날짜, 제품 코드, 참가조건의 출처가 있는 사실 후보를 만들고, 명시적인 조건은 항목별 규칙으로 판정. Gemma는 문장의 역할·적용성처럼 해석이 필요한 부분을 담당. [구현 기록](docs/clean_reference_l41_dev200_result.md)
- **출력:** 항목별 판정 주체를 하나로 고정. 모델이 반환한 원문 위치나 짧은 인용문은 Python이 실제 문서와 대조해 근거 열로 변환·검증. 근거가 무효여도 판정값을 조용히 바꾸지 않음. [입력·판정 계약](docs/clean_reference_l41_semantic_contract_20260921.md)

## Takeaways

- **모든 판정을 LLM에 맡길 필요는 없었다.** EXP120에 공식 금액·참가자격 관계 등의 고정 규칙 세 개만 합친 EXP123은 로컬 **0.2489 → 0.3178**, 공개 **0.2443 → 0.2604**. 더 큰 구조 전환을 거친 S001은 공개 **0.6054**. 문자열 하나로 법률 판단을 대체하기보다, 코드 일치·수치 비교처럼 관측과 계산이 닫힌 조건부터 Python에 맡기는 방식이 효과적이었다. [규칙 합성 결과](incubator/docs/inc123_exp120_frozen_rule_composition_result.md)
- **근거 요구는 모델의 판정에도 영향을 줬다.** 같은 입력의 초기 fast20 비교에서 Gemma의 V/E 출력은 **0.1720**, V-only는 **0.1375**. V-only는 출력 토큰을 76% 줄였지만 드문 양성을 더 놓쳤다. 별도 32건 비교도 V/E **0.2550**, V-only **0.1347**. 적어도 이 전체항목 판정 구조에서는 근거를 함께 요구하는 편이 양성 재현에 유리했다. [fast20 비교](docs/exp125_exact_vonly_probe_result.md) · [32건 비교](incubator/docs/inc121_output_contract_anchor_pilot_result.md)
- **후반의 개선은 순수 V-only 전환이 아니었다.** Python이 직접 판정하는 항목에는 모델의 자유형 근거 생성이 필요 없었다. Gemma가 남아 있는 항목도 사실 상태·원문 위치 ID, 일부는 짧은 인용문을 반환했고, Python이 원문 부분문자열로 확인했다. 즉 *판정 과정에는 원문 근거를 남기되, 제출용 근거 문구의 복사·검증은 기계적으로 처리*한 구조. S001의 점프를 근거 출력 제거 하나의 효과로 해석할 수는 없다. [최종 판정 구조](docs/clean_reference_l41_semantic_contract_20260921.md)
- **기계 규칙의 경계는 문장의 역할이었다.** ‘지역’이 참가자 소재지 제한인지 평가 가점·과거 납품처인지, 제품 코드가 이번 구매대상인지 단순 언급인지에 따라 결론이 달라진다. 비라벨 공고 감사에서 이런 역할 혼동을 확인했다. 키워드 탐지는 후보 생성에 쓰되, 예외·적용성·부재를 완전히 관측하지 못한 경우에는 자동 판정으로 승격하지 않는 편이 안전하다. [원문 역할 감사](docs/clean_exp_s020_direct_owner_source_role_audit_result.md)
- **로컬 점수와 제출 가능성을 별도로 봐야 했다.** S001은 로컬 **0.8151**, 공개 **0.6054**. 제한경쟁은 dev200의 67.5%, 비라벨 2만 건의 42.4%였고 소액수의는 17.5%와 44.8%였다. 이 차이가 실제 공개 오차에 얼마나 기여했는지는 항목별 정답 없이 분리할 수 없다. 또한 문서 분할 × 항목 그룹화는 호출 수를 키워 여러 차례 2시간을 초과했다. 배치 크기는 호출 총량을 줄이지 않는다. [분포 감사](docs/clean_exp_s004_generalization_shift_audit_result.md) · [실행 기록](docs/submission_lessons.md)

## If Revisited

- 먼저 항목별로 **기계적으로 확정 가능한 조건 / 의미 해석이 필요한 조건 / 관측되지 않은 조건**을 구분. 원문 위치와 문서 역할을 보존한 사실 후보를 공통 입력으로 사용.
- 개발셋 오류를 보고 만든 규칙은 별도 검증 대상으로 격리. 한 번에 한 판정 주체만 바꾸고, 정책 선택에 쓰지 않은 공고에서 양성 재현율·오탐을 확인.
- V/E와 짧은 구조화 출력의 정확도·근거 품질·토큰을 같은 입력에서 비교. 제출 전 원문 근거 무결성, 논리적 호출 수, 평가 환경에 가까운 추론시간까지 확인.

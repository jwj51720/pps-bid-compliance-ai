## 결정

1. S001 Python 전체를 일괄 제거하거나 label 0으로 만드는 안은 **기각**한다. 비라벨 발화율은
   오류율이 아니고, 기존 dev 반사실도 이를 지지하지 않는다.
2. `v5/v8`과 `v1/v2/v6`, 그리고 S007의 제품·absence 공통 경로를 **높은 일반화 위험**으로
   표시한다. 특히 v5의 금액×지역, v8의 실적×지역처럼 결합 조건의 source role 검증이
   필요하다. 이는 특정 단어 blacklist를 추가하라는 뜻이 아니다.
3. 다음은 한 item의 lexical patch가 아니라, hash 고정 비라벨 표본에서 *규칙이 인용한
   실제 원문 역할*을 owner군별로 블라인드 감사한다. 참가 제한/안내/서식/예외, 구매대상,
   metadata와 원문 간 충돌을 분류하되 pseudo-label을 만들지 않는다. 경로별 재현 가능한
   의미 오류가 확인된 경우에만 그 경로를 source-grounded observation으로 강등하거나
   대체한다.
4. 공식 지역제한 금액 selector 수정은 법령 공지에 따른 correctness 변경이며, S019의
   과적합 제거와 다른 축이다. 둘을 같은 ablation에 섞지 않는다.
5. 변경 후보는 한 번에 하나의 owner/policy만 바꾸고 fast→별도 검증→dev200 및 public
   비용/시간을 순서대로 본다. 비라벨 20k만으로 성능 향상을 선언하지 않는다.

한계: v20/v21/v23은 base Gemma 출력에 의존해 비라벨에서 final label을 재현할 수 없다.
v3/v19/v24는 기존 S010/S012/S013의 모집단 source-surface 감사로만 평가했다. 이 보고서는
Python 전략의 **노출/취약성 지도**이지 전체 public 오류의 인과 분해가 아니다.

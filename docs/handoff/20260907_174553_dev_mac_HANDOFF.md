## Main conclusions

1. **Raw law/RAG and larger context are not the default direction.** Earlier
   full-law bundles, law-routing bundles, cards with excessive detail, and
   document-level full split repeatedly reduced recall or multiplied runtime.
   The canonical knowledge policy remains compact organizer item definitions
   and, only when separately justified, versioned decision cards—not raw law
   text in a model message.
2. **The prompt/input contract was a real source of past experiment errors.**
   A valid YAML config or tokenizer count did not prove an active v item had
   its applicability fact, legal condition, source type, and required meta
   fact in the actual rendered message. `AGENTS.md` now requires a
   semantic-input contract and rendered-message review before paid prompt
   calls.
3. **A global whole-notice second adjudication does not generalize.** EXP144
   fast-20 and EXP145 independent holdout-20 looked positive, but the frozen
   EXP146 dev-200 confirmation did not. Never promote it or tune its wording
   item-by-item.
4. **A disjoint two-way output partition is the only grouped structure with a
   repeated quality signal.** It is not a vote or a Python rule: both calls
   read the same organizer 4,000-character input and each owns non-overlapping
   final v columns. This is today’s bounded submission candidate.
5. **Do not combine v grouping with document full split.** EXP044 timed out in
   public execution. Batch size cannot reduce the `contexts × groups` call
   count.

## Experiment record and evidence

### Exact organizer control and prompt scope

The clean control uses an ordered 4,000-character organizer-format context,
human-readable organizer metadata lines, the plain official item list, V/E
JSON, no cards, no product facts, and no legal reference bundle. Historical
configs include `configs/config.exp125a-exact-baseline-ve-fast-panel.yaml` and
the dev-200 organizer control EXP109 (reported in the result documents).

The important repeated observation is not that every fancy prompt loses, but
that an intervention must be compared with the exact same message contract.
Past V-only, card, full-context, and grouping runs often changed multiple
variables simultaneously; they are not interchangeable controls.

### EXP130–135: organizer-format output partition

The source files and results are:

- `configs/config.exp130-four-group-organizer-fast-panel.yaml`
- `configs/config.exp133-two-way-g02-fast-panel.yaml`
- `configs/config.exp134-two-way-g02-holdout.yaml`
- `configs/config.exp135-two-way-g02-dev200.yaml`
- `docs/exp130_four_group_organizer_result.md`
- `docs/exp133_two_way_g02_result.md`
- `docs/exp134_two_way_g02_holdout_result.md`
- `docs/exp135_two_way_g02_dev200_result.md`

Four-way grouping looked strong on fast-20 but did not improve full dev-200.
Counterfactual replacement identified only the document-restriction scope as
repeatedly useful. The real, disjoint two-way execution was then verified:

| Cohort | Single organizer control | Two-way G02 | Result |
| --- | ---: | ---: | --- |
| frozen fast-20 | 0.17196 | 0.26151 | positive |
| independent holdout-20 | 0.12500 | 0.20833 | positive |
| dev-200 | 0.22350 | 0.24694 | positive |

The partition is:

- `G01_remainder_items`: `v1`–`v5`, `v10`–`v18`, `v20`–`v24` (19 items)
- `G02_document_restrictions`: `v6`, `v7`, `v8`, `v9`, `v19` (5 items)

Both receive byte-identical user text for a notice; only their system item list
and output schema differ. The final row is a disjoint union. No raw law,
card, retrieval, product context, label override, overlap, voting, OR/AND
merge, or document split is involved.

An important limitation is recorded in `docs/exp135_prompt_visibility_audit.md`:
for v9 positives, the actual 4,000-character organizer context did not show
the gold specification source in any of six dev-positive notices. Do **not**
patch that with a positive default or a keyword rule. A complete-source v9
pass is a separate runtime-risk hypothesis, not part of today’s candidate.

### EXP139–142: overlay / semantic verifier rejection

`docs/bounded_multicall_verifier_strategy_v1.md`,
`docs/semantic_input_contract_v1.md`, and
`docs/exp142_semantic_verifier_preview_plan.md` document the audit.

The apparent A/B/C design was rejected before paid calls because the later

### EXP143–146: label-only second adjudication

Implementation/configs:

- `configs/config.exp143-two-pass-adjudication-preview.yaml`
- `configs/config.exp144-two-pass-adjudication-fast-panel.yaml`
- `configs/config.exp145-two-pass-adjudication-holdout.yaml`
- `configs/config.exp146-two-pass-adjudication-dev200.yaml`
- `docs/two_pass_adjudication_v1_plan.md`
- `scripts/inspect_two_pass_adjudication.py`

The design was intentionally simple: pass A runs the exact full 24-item
organizer prompt; pass B gets the same original message plus A’s 24 labels as
an explicitly untrusted, non-evidence review draft; B is the final decision.
No per-item merge or rule is used. Exact preview messages were reviewed for a
short notice, overflow notice, and attachment notice. The draft added 324
Gemma-template tokens and remained inside the admission budget.

| Cohort | A macro F1 | B macro F1 | Delta |
| --- | ---: | ---: | ---: |
| fast-20 (EXP144) | 0.15853 | 0.18168 | +0.02315 |
| independent holdout-20 (EXP145) | 0.12500 | 0.16667 | +0.04167 |
| dev-200 (EXP146) | 0.21300 | 0.21121 | **-0.00179** |

EXP146 ran all 200 records in 1,139.5 seconds. B reduced FP 277→230, but TP
also fell 49→46 (FN 104→107). One notice, `PPS-DEV-160`, hit 8,192 completion
tokens in both A and B, generated malformed JSON, and took 177.6 seconds.
The pipeline recorded whole-record recovery, but the behavior is submission
risk. **Conclusion: reject global two-pass adjudication.**

## Continuation order

1. If the current package is submitted, capture its exact public runtime and
   score in `docs/submission_lessons.md`; do not reinterpret it using dev-only
   changes.
2. Do not run another global two-pass adjudication, document-split × grouping,
   or law/RAG prompt experiment.
3. Before any paid prompt call, make a compact experiment plan with a stated
   base config and one allowed policy change. Export/read exact messages for
   short, overflow, and attachment notices; then fill the semantic-input
   contract for every active v item.
4. The next defensible large hypothesis is source-complete information for a
   *small, semantically isolated scope* (v9 is the documented example), but
   only if call count, exact source coverage, and output contract are reviewed
   before paying. It must be tested against the EXP135 two-way control as a
   single changed policy—not combined with cards, RAG, a new decoder, or a
   verifier loop.
5. A separate future branch may investigate unlabeled organizer data only
   after a label-free/source-grounded retrieval feasibility audit demonstrates
   a real signal. The present audits do not justify a 20,000-notice teacher
   labeling expense.

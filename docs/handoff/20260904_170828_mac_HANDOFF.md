## What the document-length experiments actually did

Do not misdescribe these as split/merge experiments. Exact Gemma tokenizer
admission showed **one pass for every dev200 notice** in all three cases:

| Experiment | Visible source text | Budget | one-pass / overflow / calls |
|---|---|---:|---:|
| EXP109 | ordered documents, character-capped at 4,000; in practice announcement front dominates | 14,848 | 200 / 0 / 200 |
| EXP118 | full announcement only | 31,232 | 200 / 0 / 200 |
| EXP113 | full announcement plus all attachments | 31,232 | 200 / 0 / 200 |

At the 4,000-character policy, no dev notice actually included attachment body
text: the announcement filled the character cap first. EXP115/116 therefore
only removed `[미수록 문서]` marker text and are correctly marked diagnostic;
they are **not** evidence about attachment quality.

Observed dev200 outcomes:

- EXP109: TP 49, FP 232, FN 104; F1 0.22350.
- EXP118: TP 47, FP 248, FN 106; F1 0.19101.
- EXP113: TP 44, FP 280, FN 109; F1 0.17559.

The degradation is primarily additional false positives, not merely missed
evidence. From 4k to full announcement, TP falls by 2 while FP rises by 16.
Adding attachments then loses 3 more TP and adds 32 FP. Evidence validity rises
slightly (`0.785` EXP109 to about `0.824` EXP113/118), so the model is often
finding a real source substring but applying the legal violation condition too
broadly. Items with especially unstable/over-positive behavior include v13,
v17, v19, v21, and v24; v9 gains recall from attachments but its precision stays
very low. Treat additional contextual keywords as a distractor/over-generalization
risk.

## Decision-card conclusion

The EXP109/113/118 comparison kept cards absent in all arms; it cannot by itself
attribute the length effect to cards. EXP119/120 is the proper isolated test:
the EXP109 prompt, 4k context, V+e schema, model, decoding, and metadata all
remain fixed; only `decision_cards_v6.json` is added. DEV200 improves
`0.22350 -> 0.24893` (+0.02543). This supports the hypothesis that compact,
explicit applicability/1/0/exception criteria reduce keyword-driven false
positives.

Canonical knowledge rule going forward:

1. Do **not** inject raw laws, article excerpts, law summaries, or large
   self-labeled corpora at runtime.
2. Review organizer law offline, preserve provenance, and encode compact
   conditions in a versioned decision-card artifact.
3. Supply only human-readable necessary metadata/product facts, then actual
   notice text. Evidence must remain a literal notice substring.
4. Do not introduce Python semantic gates for fuzzy wording; use Python only
   for explicit LLM-output combination/validation.

## 16k versus 32k card-v6 + full-announcement analysis (not yet a paid run)

After EXP120, the user asked whether increasing the token window is necessary
to test the full announcement. The answer is yes: `max_model_len` alone does
nothing while `max_document_chars: 4000` remains set. A full-announcement
experiment must set `max_document_chars: null`.

Exact Gemma-tokenizer calculation for **card v6 + announcement only + V+e**:

| Prompt budget | Fits in one call | Would overflow |
|---:|---:|---:|
| 16k model length minus 1,536 output = 14,848 | 194 / 200 | 6 / 200 |
| 32k model length minus 1,536 output = 31,232 | 200 / 200 | 0 / 200 |

Median/p95/max prompt tokens are 8,531 / 13,660 / 27,510. Therefore the clean
next ablation is **card v6 + announcement only + full text + 32k**, with
`overflow_split_enabled: true` only as a safety behavior (it will not execute
on dev200). It changes `max_document_chars`, overflow admission, and
`max_model_len` relative to EXP120; declare all three in
`allowed_policy_changes`. Do not call it a 16k comparison. A separate 16k
adaptive-overflow ablation would deliberately test 6 split notices and should
be named and interpreted separately.

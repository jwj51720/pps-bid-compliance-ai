# Native metadata-fact contract (N1 continuation)

작성일: 2026-09-21

독립 prompt는 원본 `meta` JSON을 넣지 않는다. 카드 v31의 판정 조건에서
필요한 organizer 입력 필드를 항목별로 골라 한국어 사실 문장으로 렌더링한다.
이 단계의 Python은 값의 표현·출처만 관리하고 법률 적용, 예외, V 라벨은
결정하지 않는다. 경쟁제품 exact-code 사실은 별도 native product 모듈의
v10–v18 입력으로 연결한다.

필드 구분:

- 금액: `입찰추정가격`과 `배정예산금액`을 서로 다른 명칭으로 유지한다.
- 방식: `계약방법`(경쟁 방식)과 `낙찰방법`(협상 여부)을 혼동하지 않는다.
- `소관구분`만으로 공기업 계약사무규칙의 실제 적용을 확정하지 않는다.
- 지역/업종: flag와 목록을 별도 사실로 유지한다. 등록지역 내부 표현은
  광역·기초 정보만 사람 말로 옮기고 없는 세부 시군구는 만들지 않는다.
  업종목록은 이름·4자리 식별번호의 대응과 AND/OR 연결을 보존하되,
  raw 코드 배열 대신 `업종명 [업종식별번호 NNNN]` 형태로 바꾼다.
  v24의 정확한 동일 필드 비교에는 그 대응이 필요할 수 있다.
- `조항호내용`은 전자조달 입력의 기재 사실로만 제시한다. 이것만으로
  실제 예외가 적용된다는 추론을 하지 않는다.
- null/`미입력`은 `확인되지 않음`으로 표현한다. 없는 값을 부정 사실로
  바꾸지 않는다.

이후 검증은 200개 공고의 모든 21개 metadata key 존재, 각 항목에 할당된
field의 렌더 성공, raw JSON/internal status 미노출, 금액/날짜 정확성,
v24의 상세 업종 provenance gap을 대상으로 한다. 별도 full-source prompt
렌더링과 24개 semantic-input audit 전에는 유료 실험으로 진행하지 않는다.

# INC-113/114: general-product specialist diagnosis

INC-113 added the organizer exact competition-product status to a full-source
high-reasoning Luna specialist for v12/v14/v15/v17 on 16 label-free structural
notices.  Compared with INC-088 on the same IDs, target-family F1 rose from
0.000 to 0.1667 through one v17 true positive, but introduced two false
positives.  The second fresh 16-notice run (INC-114) strengthened the contract
so metadata could not create a source-absent restriction.  It still produced
one v15 true positive, but four v17 and one v14 false positives.

The shared finding is that exact product non-match correctly supplies only the
*general-product* premise.  It is neither a violation label nor a sufficient
exception analysis.  Source inspection confirms that the remaining errors
depend on legal eligibility/exception structure not represented in the terse
card: a source can contain an actual small-business restriction yet be lawful,
while another nearly identical restriction can be unlawful.

**Decision:** do not merge either specialist into INC-088 or run dev-200.
The next viable product-family branch must provide the relevant
organizer-supplied legal text for the exception decision, in addition to the
exact product status and original notice.  This is a legal-context hypothesis,
not a numeric calibration.
